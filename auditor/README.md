# Elastispec Auditor

Given a specification of the vendor document in the Elastispec Domain Specific
Language (DSL) format, the Auditor checks whether a firewall configuration meets
the specification. The DSL specifications of many popular enterprise
applications are available [here](specifications/). If you are dealing with an
application not on this list, you should use the
[Elastispec Translator](../translator/README.md), which converts the vendor
document to the DSL.

Only vendor documentation is sent to an LLM provider; all other inputs,
including firewall configurations, remain local.

## Quick Start: Simplified PaperCut Example

This example uses a simplified specification for
[PaperCut](https://www.papercut.com/), a popular print management application.
Run these commands from the repository root with Docker running. The example
includes all three inputs. The runner downloads the public Auditor and Batfish
images from Docker Hub when needed.

### Linux x86_64 / amd64

```bash
./auditor/scripts/run_auditor_docker.sh \
  --config auditor/examples/papercut_toy/toy_firewall_config.txt \
  --inventory auditor/examples/papercut_toy/inventory.json \
  --spec auditor/examples/papercut_toy/papercut_toy.fsl \
  --output auditor/output/papercut_toy.html \
  --title "PaperCut firewall audit"
```

### Windows x64

Use PowerShell with Docker Desktop configured to run Linux containers:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\auditor\scripts\run_auditor_docker.ps1 `
  -Config auditor\examples\papercut_toy\toy_firewall_config.txt `
  -Inventory auditor\examples\papercut_toy\inventory.json `
  -Spec auditor\examples\papercut_toy\papercut_toy.fsl `
  -Output auditor\output\papercut_toy.html `
  -Title "PaperCut firewall audit"
```

The results are available at `auditor/output/papercut_toy.html`. The
[PaperCut tutorial](TUTORIAL.md) explains the inputs, compliance report, and
provides more information.

## Run With Your Own Inputs

Keep the Docker unchanged and replace the parameters below. On Linux:

```bash
./auditor/scripts/run_auditor_docker.sh \
  --config /absolute/path/firewall.cfg \
  --inventory /absolute/path/inventory.json \
  --spec /absolute/path/policy.fsl \
  --output /absolute/path/audit-report.html \
  --title "Campus firewall audit"
```

On Windows PowerShell:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\auditor\scripts\run_auditor_docker.ps1 `
  -Config C:\path\to\firewall.cfg `
  -Inventory C:\path\to\inventory.json `
  -Spec C:\path\to\policy.fsl `
  -Output C:\path\to\audit-report.html `
  -Title "Campus firewall audit"
```

| Argument | Input |
| --- | --- |
| `--config` / `-Config` | Complete Cisco IOS or ASA configuration |
| `--inventory` / `-Inventory` | Server inventory JSON |
| `--spec` / `-Spec` | Elastispec `.fsl` specification |
| `--output` / `-Output` | New compliance report path |
| `--title` / `-Title` | Optional report title |

## What You Need

| Input | Requirement |
| --- | --- |
| Firewall configuration | Cisco IOS or ASA configuration (Currently other vendors are not supported) |
| Server inventory | One JSON file mapping application roles to IPv4 addresses or CIDRs |
| Elastispec specification | The `.fsl` file generated by the Elastispec Translator from the vendor document (FSLs of many popular applications have been pre-generated) |

## Creating An Inventory File

The server inventory is a JSON object. Each top-level key is a role referenced
by the specification. Role names must match the specification exactly.

```json
{
  "PaperCut_Application_Server": {
    "host_ip": ["172.16.10.2", "172.16.10.3"]
  },
  "PostgreSQL_Database": {
    "host_ip": ["172.16.20.40"]
  },
  "Oracle_Database": {
    "host_ip": ["N/A"]
  },
  "Mobility_Print_Update_Services": {
    "host_ip": ["web"]
  },
  "PaperCut_Clients": {}
}
```

| Value | Meaning |
| --- | --- |
| `{"host_ip": ["172.16.10.2", "10.1.0.0/16"]}` | The role is mapped to these IPv4 addresses or CIDRs. |
| `{"host_ip": ["N/A"]}` | Not applicable as role known not to be deployed |
| `{"host_ip": ["web"]}` | The role is an external server. The Auditor skips external server policies. |
| `{}` or an omitted role | The role is unresolved. The report may show a conjecture when the configuration permits a candidate source range. |

Create the server inventory manually using the format above. For a provided
application, start with the inventory template listed below and fill it using
the enterprise inventory. If the enterprise inventory uses a different format,
transfer its role-to-IP mappings into this JSON structure manually. An automated
tool for populating the inventory is under development and will be released
separately.

## Read The Report

The compliance report contains a collapsible compliance tree and three verdicts:

| Verdict | Meaning |
| --- | --- |
| `VALID` | The related roles have explicit inventory mappings and the configuration satisfies the requirement. |
| `CONJECTURED-SAT` | A role is unresolved, but the Auditor found candidate address ranges that satisfy the requirement. |
| `UNSAT` | The configuration does not satisfy the requirement under the available mappings. |

The `Conjectures` table lists candidate ingress interfaces and source prefixes
for unresolved source roles. Validate those ranges against the intended campus
or security zone. An `UNSAT` leaf in an `OR` or optional branch does not always
make the root `UNSAT`; inspect the full tree.

See the [PaperCut tutorial](TUTORIAL.md) for a concrete report walkthrough.

## Python Source Mode

Python 3.14 and a running Batfish container are required.

```bash
python3 -m venv auditor/.venv
source auditor/.venv/bin/activate
python -m pip install -r auditor/requirements.txt
```

Start Batfish by following
[Docker Mode 2](DOCKER.md#mode-2-python-source-with-batfish-container), then run:

```bash
python auditor/scripts/run_auditor.py \
  --config /path/to/firewall.cfg \
  --inventory /path/to/inventory.json \
  --spec /path/to/policy.fsl \
  --output /path/to/audit-report.html \
  --batfish_data_dir "$BATFISH_DATA_DIR"
```

| Argument | Required | Purpose |
| --- | --- | --- |
| `--config` | Yes | Complete Cisco IOS or ASA configuration |
| `--inventory` | Yes | Server inventory JSON |
| `--spec` | Yes | Reviewed Elastispec specification |
| `--output` | Yes | Compliance report path |
| `--title` | No | Report title |
| `--batfish_data_dir` | No | Host directory mounted at `/data`; defaults to `~/batfish-data` |
| `--batfish_host` | No | Batfish hostname; defaults to `localhost` |
| `--batfish_startup_timeout` | No | Seconds to wait for Batfish startup |

For container details and the alternative Python source mode, see
[DOCKER.md](DOCKER.md). Run one Auditor process at a time per Batfish data
directory or Compose volume.
